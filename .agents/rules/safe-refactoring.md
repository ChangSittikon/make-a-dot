# Safe Refactoring & Modularity (การจัดการโค้ดอย่างปลอดภัย)

เพื่อป้องกันปัญหาการแก้ไขโค้ดแล้วไฟล์พัง โครงสร้างเพี้ยน จนต้องเสียเวลาซ่อมแซมเป็นเวลานาน AI เอเจนต์และนักพัฒนาต้องปฏิบัติตามกฎเหล่านี้อย่างเคร่งครัด:

1. **ห้ามแบ็คอัพไฟล์แบบ Manual:** ห้ามสร้างไฟล์สำรองแบบตั้งชื่อเองเช่น `Component_old.tsx` หรือ `Component_backup.tsx` โดยเด็ดขาด ให้ใช้ระบบ **Version Control (Git)** ในการบันทึกสถานะของโค้ดแทน และต้อง Commit ทันทีที่ส่วนย่อยผ่าน และ Push ขึ้น GitHub เสมอ
2. **แยกคอมโพเนนต์เสมอ (Component Modularity - Hard Limit 300 บรรทัด):** ไฟล์ React Component / Page ห้ามมีขนาดเกิน 300 บรรทัด หากหน้านั้นมี Modal, แท็บย่อย หรือข้อมูลจำลองขนาดใหญ่ **ต้องแยก (Extract) ออกเป็นคอมโพเนนต์ย่อยทันที** เช่น แตกเป็นโฟลเดอร์ `/tabs`, `types.ts`, `constants.ts` เพื่อป้องกันปัญหาไฟล์ยักษ์และการเกิด Syntax Error ลุกลามทั้งหน้า
3. **ห้ามแทนที่โค้ดด้วย Script ตัดแปะสุ่มเสี่ยง (No Blind Batch Script Replacement):** ในการแก้ไขโค้ด เอเจนต์ห้ามใช้วิธีการเขียน Script Shell (เช่น PowerShell/Bash) เพื่อตัดและแทนที่โค้ดทีละหลายร้อยบรรทัดแบบสุ่มเสี่ยงเด็ดขาด ให้ใช้เครื่องมือแก้ไขโค้ดที่ระบุบรรทัดอย่างแม่นยำ (Line-by-line patching)
4. **ตรวจสอบการคอมไพล์ทุกครั้ง:** หลังจากการแก้ไขไฟล์สำคัญ จะต้องอ่าน Log ของ Next.js และรัน `npx tsc --noEmit` เสมอ เพื่อตรวจสอบว่าโค้ดสามารถคอมไพล์ได้ผ่าน 100% ก่อนจะสรุปงานให้ผู้ใช้ฟัง
